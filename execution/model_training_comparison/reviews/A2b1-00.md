1. **Timer and ledger-failure cleanup are incomplete.**  `OwnedAttempt` replaces
   `SIGALRM` but only disarms the timer; it never saves/restores the prior signal
   handler or prior timer.  A returned attempt therefore mutates its host process,
   and setup/finalization exceptions can leave handler state changed.  Preserve,
   cancel and restore both previous handler/timer on every success/failure path.
   Add an actual timer-expiry test and handler/timer restoration assertions.
   Separately inject ledger append/open/fsync failure during finalization: it must
   surface explicitly, clean lock/timer, preserve the attempt artifact or a clear
   failure artifact, and never emit a false successful summary.  The current test
   covers only `attempt.json` write failure, not ledger failure.

2. **Scheduled gradient/update summaries are neither complete nor correctly
   separated from core timing.**  `train_step` computes a redundant full preclip
   gradient norm and pre-update weight norm inside every core-timed step even when
   `summary=False`.  It then defines update/weight ratio as the absolute change in
   *total weight norm*, which is not `||parameter update|| / ||weights||` and can
   cancel across tensors.  Use the norm returned by clipping for global preclip
   norm; only on scheduled summary steps snapshot tensors and compute the actual
   update-vector norm ratio outside the core timer.  Add the frozen group norms,
   per-layer/head alpha/beta or dt/gamma values, summary duration and total-step
   duration.  Tests must prove ordinary steps skip summary extraction, core time
   includes materialization-excluded forward/backward/finiteness/clip/step only,
   and end-to-end is at least the sum of reported phases.

3. **Checkpoint immutability and identity chain are under-specified in code.**
   `torch.save(payload, path)` silently overwrites an existing checkpoint.  Make
   checkpoint creation fail if the target exists and bind/hash the exact parent
   checkpoint for every noninitial checkpoint.  Store explicit immutable input
   identities (training bundle/support, paired minibatch stream/config/source),
   not only an unconstrained caller string/dict, and validate them plus update/
   mode/seed/initial hash on restore before changing live model/optimizer/RNG
   state.  Tests should reject overwrite, wrong source/config/input/parent/mode
   and demonstrate next-batch and parameter equality after a noninitial chained
   restore.  No fallback or partial mutation on identity rejection.

4. **Paired-core evidence needs literal batch/optimizer assertions.**  The test
   creates same-seed samplers but does not assert the paired next-batch identity
   hash, separate optimizer-state identity, or complete SA checkpoint replay.
   Assert identical batch prefixes for the two architectures, distinct optimizer
   objects/states, finite gradients/parameters for both, and at least one exact SA
   interrupted/resumed continuation in addition to the softmax path (a very short
   split is sufficient).  This closes the paired complex-autograd resume risk
