   Each profile cell measures only the current model's greedy, T1 K32 and proper

   future temperature work to `NOT_IMPLEMENTED_GATED`/`None`.  Those operations
   are required in the pre-pair forecast even if their later analysis code is
   deferred.  Measure representative per-operation costs or use an explicit
   conservative measured upper bound, then multiply the exact frozen candidate
   counts.  A forecast that omits them cannot gate pair 1701.

2. **Probe selection and scaling do not match the frozen banks.**
   `fixed_probe_candidates` takes eight states from every map.  In CLI training
   this is not the fixed first four I and first four L training maps (64 states)
   plus first four I, first four L and all eight mixed validation maps (128
   states).  The profile instead probes only its six-map heldout subset (48
   states), then scales that one SA call as if it represented both models at all
   three endpoints.  Implement separately identified training/validation probe
   selectors with literal 64/128 counts and family/map IDs; profile proportional
   cost for the complete 192-state scheduled probe workload.  Softmax's mechanism
   probe is explicitly nonapplicable and must not be charged as an SA probe, while
   the forecast must still count every genuinely required endpoint operation.

3. **Profile timing cells are not nonoverlapping or tied to the real ledger.**

   `stratum_cells`; setup is then computed by residual subtraction and can mask
   overlap with `max(0, ...)`.  `ledger_seconds` reads the guessed path
   `out.parent/ledger.jsonl`, although the CLI accepts an arbitrary `--ledger`,
   and it does not measure append/fsync/finalization.  Pass the actual ledger
   identity into profiling and save separately timed, nonoverlapping setup,
   warmup, training core/end-to-end, per-operation evaluation, verifier,
