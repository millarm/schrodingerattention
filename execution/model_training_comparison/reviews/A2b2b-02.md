Static review only; no command was run and no ledger charge was added.  This was
the second/final correction cycle, so unresolved requirements are recorded as an
implementation blocker rather than another local correction request.

Closed portions of A2b2b-01 include literal 64/128 selector cardinalities,
current/initial/uniform profile calls, positive conservative temperature-work
arithmetic, physical 384/128 × two-model × three-endpoint scaling, post-finalize
CLI output, basic 1701 run binding and support-aware standalone evaluation.

Material residual blockers:

1. **No real profile or composed CLI-train path is tested.**  No test invokes
   `command_profile`, and the only `_cli` test replaces `command_prepare` with a
   lambda.  There remains no executing regression for five warmups plus twenty
   measured updates/model, six maps/96 problems, real evaluator/probe/checkpoint
   serialization, either CLI training mode, scheduled 0/500/1000 events, exact
   resume, or the successful artifact/provenance composition.  Selector and
   arithmetic unit tests do not establish that the command to be launched works.

2. **Profile accounting remains synthetic and overlapping.**  Profile
   `controls_seconds` wraps the same operations used to form `stratum_cells`,
   while setup is a residual subtraction clamped with `max(0, ...)`.  Most
   importantly, ledger cost is measured by reading the guessed path
   `out.parent/ledger.jsonl` (line 397), not the CLI's arbitrary `--ledger`, and
   does not measure append/fsync/finalization.  Thus the supposedly complete
   nonzero forecast units are not bound to the actual owned command and cannot
   support the resource gate.

3. **The profiled probe workload still differs from scheduled pair work.**
   `command_profile` probes only the 128-state validation bank (line 394), not the
   separately identified 64-state training plus 128-state validation workload.
   Pair training concatenates both banks before `mechanism_probe`, losing an
   explicit training-versus-validation origin for overlapping routine families.
   The forecast scales one 128-state SA timing as if it represented every
   required scheduled probe.  Literal selector counts do not repair that cost or
   provenance mismatch.

4. **Profile evidence is not auditable as completed science.**  The profile saves
   only per-operation timing dictionaries and discards evaluator metrics, probe
   records/numerical summaries, cache/count identities and checkpoint hashes/
   bytes.  Consequently the recorded 96-problem and 192-probe operations cannot
   be independently confirmed from outputs.  The source inventory also remains
   the same narrow list and no output path→SHA256 manifest binds checkpoints,
   curves, events, profile and result artifacts.

5. **Fresh-run identity remains insufficient for controlled resume.**
   `scheduled_training` still returns `initial_hash` (model-state hash) but not
   the immutable initial checkpoint file hash required by a later resume
   decision.  Tests do not substitute a different original initial checkpoint,
   do not exercise wrong seed/mode/update through `_require_run_binding`, and do
   not prove own-initial control replay from the exact recorded file.  The resume
   checker itself is improved, but the successful fresh result does not emit all
   information needed to authorize it.

The reported A/global totals are `289.000238584 / 1212.003835837` seconds.  These
findings concern harness execution/provenance, not the accepted model, evaluator,
dataset, or scientific plan.  Production must remain stopped pending a parent
role/respecification decision; no profile output should be treated as a resource
gate and no pair1701 training is authorized from this version.
